Pnapana · motion system

Scroll behaviour spec

Every effect on the homepage is CSS scroll-driven animation — no scroll listeners, no IntersectionObserver, no animation library. The work happens off the main thread, so the page stays smooth while it moves.

The rule that keeps it safe

Author every element in its final, visible state, then layer motion inside @supports (animation-timeline: view()). A browser without scroll timelines shows a finished page instead of a blank one — the usual failure mode of scroll animation is content stuck at opacity: 0.

Easing

The standard curve is the one already used across the app's CSS — reuse it so new motion feels native.

Standard — hover, CTA, cards cubic-bezier(0.16, 1, 0.3, 1)
Scroll-linked — every timeline above linear

Scroll-driven animation must be linear. The scroll position is the clock, so any other curve makes the element lag or race the user's finger.

Entrance — modals, toasts cubic-bezier(0.22, 1, 0.36, 1)
